Before you start

Check the source date at the top of the checker. It shows a captured set of public notices, not a live operations feed. If you need the latest schedule, open the original notice before acting.

Four steps

  1. Read Needs review. Compare the two fields shown under each finding. “Blocked from calendar” means the schedule cannot be used as written. “Review only” calls attention to something worth checking.
  2. Open the original notice. Read its latest update, location and scheduled times. Do not pick a value just because it appears in the title. If the source still disagrees with itself, keep the record unresolved.
  3. Check Calendar. Only active or upcoming maintenance that passes the blocking checks is included. Held records are listed separately. The checker has no manual approval button: a corrected source must pass a later refresh before the record can enter the export.
  4. Prepare the handoff. Download the summary and calendar from Summary. The summary includes unresolved active or upcoming maintenance. Older findings remain in Needs review. The calendar contains only the entries that passed the checks. Send the files through your normal review process only after checking their contents.

A real conflict

In the September 3 capture, one notice was titled US-WEST-04A while its location field said US-EAST-04. The checker held that record out of the calendar. It did not decide which location was correct.

Open the original notice. The source may have changed since the capture.

What to include in a handoff

State when the source was captured, which locations and windows are ready, and which notices still need a decision. For each unresolved notice, include its source link, the conflicting values and the question that needs answering. The downloaded summary provides the starting point.

If something goes wrong

  • The data is old. Check the original status page. The public site refreshes on a schedule and retains the last successful release if a refresh fails. An old capture is not proof that nothing has changed.
  • A local refresh fails. The previous data remains visible. Check source availability before trying again. Do not describe the old export as current.
  • The calendar is empty. Read the held list and source date. There may be no qualifying upcoming windows, or notices may be blocked. Do not add a guessed time or location.
  • A date has no end time. Keep the missing time unresolved. A date-only extension does not justify inventing a time.
